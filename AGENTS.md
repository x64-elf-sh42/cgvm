# Documentation

- Keep `README.md` and `docs/` focused on the project: setup, usage, implemented
  behavior, architecture, and current limitations.
- Store session handoffs, development journals, conversation summaries, playtest
  notes, and scratch plans in `.dev-notes/`, which is ignored by Git.
- Do not link public documentation to files in `.dev-notes/`; those files are
  local and will not be available to repository visitors.
- When development changes project behavior, update the relevant public reference
  to describe the resulting behavior without adding session history.
